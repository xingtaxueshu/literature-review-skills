# 输出契约（Output Contract）

目的：让 5 个 skill 的输出结构稳定、可检查，并且每次都把“要核对什么、要作者决定什么”摆在结尾。版本 0.2.0。

## 固定规则

1. 各 skill 先输出自己 `SKILL.md` 里 Output Format 规定的主体段落，**段落名和顺序不改**。
2. `## 段落草稿（需作者改写并核对来源）` 只出现在会生成段落的 skill 里（`compare-research-methods`、`map-literature-contradictions`、`locate-review-research-gap`），位置按各自模板，不挪动。
3. 主体最后，按下面的顺序固定追加两段：
   1. `## 待核实清单`
   2. `## 给作者的问题`
4. 没有内容也要保留标题，写“无”，不要省略。
5. 涉及文献的内容遵守 [source-integrity.md](source-integrity.md)。

## 各段落写什么

**段落草稿（需作者改写并核对来源）**：只是起点，不是可直接提交的正文。开头固定提示一句：“以下为草稿，请改写成你自己的论证，并逐句核对来源后再使用。”依赖文献的句子带 `作者（年份）·状态标签` 或 `[需补来源]`。

**待核实清单**：逐条列出需要用户去核对的事项，每条写清楚“是什么、为什么要核、建议怎么核”。至少覆盖：
- 状态为 `未核验` 的文献，以及核验结果为“未查到”的文献；
- 状态为 `用户提供` 但题录有疑点的文献；
- 标了 `[需补来源]` 的句子；
- 文献库里有、但结论尚未读摘要或全文核对的论断；
- 凭 AI 推断而非文献得出的判断（标明是推断）。

**给作者的问题**：需要作者做学术判断、AI 不应替作者定的事，如研究范围取舍、概念界定、方法偏好、对矛盾的解释倾向、想强调哪个 gap。每条问题尽量可以直接回答。

## 示意

```markdown
## 待核实清单

- [未核验] 候选文献“…”：只有题名，未查到题录。建议：用 DOI 或 CNKI/万方人工检索后告诉我结果。
- [需补来源] 第 2 段“已有研究多关注……”：没有对应文献。建议：补充你读过的文献，或删去这句判断。

## 给作者的问题

1. 你更想强调条件性差异，还是保留“效应不确定”的表述？
2. 这篇综述的时间与地域范围要不要限定？
```
